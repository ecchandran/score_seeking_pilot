# Score-Seeking Pilot

I conducted a short independent study that extends Redwood Research's paper
[*Towards Understanding Score-Seeking in LLMs*](https://arxiv.org/abs/2610.41014) to test hypotheses on how score-seeking behavior and evaluation awareness differ across additional models and the extent to which an independent monitor can predict instances of model score-seeking. This pilot is motivated in part by recent reports of evaluation awareness in more capable models, and I intended to provide additional data that may help extrapolate conclusions about score-seeking to future generations of LLMs. Holding a modification of the paper's _Translation_ environment as fixed, I evaluate six different models (GPT-6 Astra, GPT-5.6 Sol, GPT-5.5, o3, gpt-oss-120b, DeepSeek V4 Pro) in a Dose-Response Experiment and Deployment-Influence Experiment similar to studies in the paper. I then examine whether models attest to having followed the user's instructions after score-seeking, rates of evaluation awareness, and the ability of a monitor model to predict score-seeking from clipped transcripts. I find significant differences in score-seeking tendencies across models and large differences in verbalized evaluation awareness (although the latter is confounded by API filtering of reasoning); statistically significant reductions in score-seeking rates for two models (GPT-5.6 Sol and GPT-5.5) when score-seeking is stated to _block_ rather than _enable_ deployment; and moderate to high accuracy in a monitor's predictions of score-seeking for most models when reasoning traces are exposed.

## Running

Requires Python 3.11+.

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.lock
.venv/bin/python -m pytest                                      # unit tests, no API calls
.venv/bin/python -m src.run configs/stage0_smoke.yaml           # end-to-end run with a scripted stub, no API calls
.venv/bin/python writeup/make_figures.py                        # regenerate write-up figures and tables
```

Real runs need `OPENAI_API_KEY` and `OPENROUTER_API_KEY` in a `.env` file (see `.env.example`)
and cost money. Pass `--dry-run` to `src.run` to see the manifest and a cost estimate first.
